Built-in

Ubuntu Touch SSH bootstrap

mkdir -p ~/.ssh && chmod 700 ~/.ssh
wget -qO- https://portal.3dvr.tech/api/ut-pair >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
sudo systemctl start ssh.socket
[ -f ~/.ssh/utunnel ] || ssh-keygen -q -t ed25519 -N '' -f ~/.ssh/utunnel
K="$(base64 ~/.ssh/utunnel.pub | tr -d '\n')"
wget -qO- --post-data="key=$K" https://portal.3dvr.tech/api/ut-pair

Next step

Open reverse SSH tunnel

ssh -i ~/.ssh/utunnel -o BatchMode=yes -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -N -R 127.0.0.1:2206:127.0.0.1:22 root@167.233.174.20

This keeps a connection open from the OnePlus to Hetzner and maps Hetzner port 2206 back to the phone's SSH port 22.

Repair phone SSH

Generate host keys + restart SSH

sudo ssh-keygen -A
sudo service ssh restart || true
sudo systemctl restart ssh.socket
systemctl --user restart 3dvr-reverse-tunnel.service
systemctl --user status --no-pager 3dvr-reverse-tunnel.service

Use this if the reverse tunnel is up but connections through it close before the SSH banner appears.

Make it permanent

Keep the tunnel alive automatically

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/3dvr-reverse-tunnel.service <<'EOF'
[Unit]
Description=3DVR reverse SSH tunnel

[Service]
ExecStart=/usr/bin/ssh -i %h/.ssh/utunnel -o BatchMode=yes -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o StrictHostKeyChecking=yes -N -R 127.0.0.1:2206:127.0.0.1:22 root@167.233.174.20
Restart=always
RestartSec=10

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable --now 3dvr-reverse-tunnel.service
systemctl --user status --no-pager 3dvr-reverse-tunnel.service

Run this after closing the manual tunnel. It moves the connection out of Terminal so it can reconnect automatically.

Ubuntu Touch power

Keep remote access alive with screen off

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/3dvr-stay-awake.service <<'EOF'
[Unit]
Description=Keep Ubuntu Touch active for 3DVR remote access
Before=3dvr-reverse-tunnel.service

[Service]
ExecStart=/usr/sbin/repowerd-cli active
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable --now 3dvr-stay-awake.service
systemctl --user restart 3dvr-reverse-tunnel.service

Uses Ubuntu Touch's native repowerd inhibitor: the display may turn off, but the device does not suspend while remote access is enabled.

Daily-driver upgrade

Upgrade Ubuntu Touch to OTA-12

sudo system-image-cli --switch 20.04/arm64/android9plus/stable

Verified stable feed for this OnePlus 6/6T port. Downloads the current Focal OTA-12 system image, then reboots to apply it. Your home data and 3DVR remote-access files stay in /home/phablet.

OTA diagnostics

Expose OTA error log

sudo mkdir -p /home/phablet/ota-debug
sudo cp /root/.cache/system-image/client.log /home/phablet/ota-debug/root-client.log
sudo cp -a /var/lib/system-image /home/phablet/ota-debug/system-image-state
sudo chown -R phablet:phablet /home/phablet/ota-debug
echo OTA_LOG_READY

Copies only the updater diagnostics/state into your home directory so 3DVR can inspect the failure remotely.

OTA diagnostics

Capture OTA failure safely

mkdir -p ~/ota-debug
sudo sh -c 'system-image-cli -n -v --switch 20.04/arm64/android9plus/stable > /home/phablet/ota-debug/ota-dry-run.log 2>&1'
sudo chown phablet:phablet ~/ota-debug/ota-dry-run.log
echo OTA_DRY_RUN_READY

Runs the updater as root in dry-run mode, captures the exact failure to your home directory, and does not reboot or apply the update.

OTA fix

Test OTA with direct downloader

mkdir -p ~/ota-debug
sudo sh -c 'SYSTEMIMAGE_PYCURL=1 system-image-cli -n -v --switch 20.04/arm64/android9plus/stable > /home/phablet/ota-debug/ota-pycurl-dry-run.log 2>&1'
sudo chown phablet:phablet ~/ota-debug/ota-pycurl-dry-run.log
echo OTA_PYCURL_TEST_READY

Forces the updater's built-in PyCURL backend, bypassing the broken Lomiri Download Manager. Dry-run only: no reboot and no update is applied.

OTA fix

Test OTA with local PyCURL

mkdir -p ~/ota-debug
sudo sh -c 'PYTHONPATH=/home/phablet/3dvr-local/pycurl-root/usr/lib/python3/dist-packages SYSTEMIMAGE_PYCURL=1 system-image-cli -n -v --switch 20.04/arm64/android9plus/stable > /home/phablet/ota-debug/ota-local-pycurl-dry-run.log 2>&1'
sudo chown phablet:phablet ~/ota-debug/ota-local-pycurl-dry-run.log
echo OTA_LOCAL_PYCURL_READY

Uses the PyCURL module unpacked into /home/phablet, bypassing the broken Lomiri downloader without modifying the read-only system image. Dry-run only.

OTA-12 ready

Install OTA-12 with local PyCURL

sudo sh -c 'PYTHONPATH=/home/phablet/3dvr-local/pycurl-root/usr/lib/python3/dist-packages SYSTEMIMAGE_PYCURL=1 system-image-cli --switch 20.04/arm64/android9plus/stable'

Verified by dry-run: upgrade path 12 is available for this device. This command downloads and applies OTA-12, then reboots the phone.

Android layer

Initialize Waydroid

sudo waydroid init -s VANILLA

Creates the Android container using Waydroid's supported vanilla LineageOS image. Android app data will live under your large /home partition.

One-time admin setup

Repair limited sudo + initialize Waydroid

sudo sh -c '
set -eu
mount -o remount,rw /
mkdir -p /usr/local/sbin /etc/sudoers.d
cat > /usr/local/sbin/3dvr-admin <<"EOF"
#!/bin/sh
set -eu
case "${1:-}" in
  waydroid-init)
    exec /usr/bin/waydroid init -s VANILLA
    ;;
  waydroid-container-start)
    exec /usr/bin/systemctl start waydroid-container.service
    ;;
  waydroid-container-stop)
    exec /usr/bin/systemctl stop waydroid-container.service
    ;;
  waydroid-container-restart)
    exec /usr/bin/systemctl restart waydroid-container.service
    ;;
  enable-linger)
    exec /usr/bin/loginctl enable-linger phablet
    ;;
  ota-stable)
    exec env PYTHONPATH=/home/phablet/3dvr-local/pycurl-root/usr/lib/python3/dist-packages SYSTEMIMAGE_PYCURL=1 /usr/bin/system-image-cli --switch 20.04/arm64/android9plus/stable
    ;;
  *)
    echo "Allowed: waydroid-init | waydroid-container-start | waydroid-container-stop | waydroid-container-restart | enable-linger | ota-stable" >&2
    exit 64
    ;;
esac
EOF
chmod 0755 /usr/local/sbin/3dvr-admin
chown root:root /usr/local/sbin/3dvr-admin
printf "%s\n" "phablet ALL=(root) NOPASSWD: /usr/local/sbin/3dvr-admin" > /etc/sudoers.d/3dvr-admin
chmod 0440 /etc/sudoers.d/3dvr-admin
if ! grep -Eq "^[#@]includedir[[:space:]]+/etc/sudoers.d" /etc/sudoers; then
  printf "\n#includedir /etc/sudoers.d\n" >> /etc/sudoers
fi
visudo -cf /etc/sudoers
mount -o remount,ro /
'
sudo -n /usr/local/sbin/3dvr-admin enable-linger
echo 3DVR_LIMITED_SUDO_READY
sudo -n /usr/local/sbin/3dvr-admin waydroid-init

One password entry installs a root-owned whitelist helper, validates sudoers, enables boot persistence, then initializes Waydroid. No password is stored and arbitrary root shells remain blocked.
