Ubuntu Touch SSH bootstrap

mkdir -p ~/.ssh && chmod 700 ~/.ssh
wget -qO- https://portal.3dvr.tech/api/ut-pair >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
sudo systemctl start ssh.socket
[ -f ~/.ssh/utunnel ] || ssh-keygen -q -t ed25519 -N '' -f ~/.ssh/utunnel
K="$(base64 ~/.ssh/utunnel.pub | tr -d '\n')"
wget -qO- --post-data="key=$K" https://portal.3dvr.tech/api/ut-pair

Next step

Open reverse SSH tunnel

ssh -i ~/.ssh/utunnel -o BatchMode=yes -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -N -R 127.0.0.1:2206:127.0.0.1:22 root@167.233.174.20

This keeps a connection open from the OnePlus to Hetzner and maps Hetzner port 2206 back to the phone's SSH port 22.

Repair phone SSH

Generate host keys + restart SSH

sudo ssh-keygen -A
sudo service ssh restart || true
sudo systemctl restart ssh.socket
systemctl --user restart 3dvr-reverse-tunnel.service
systemctl --user status --no-pager 3dvr-reverse-tunnel.service

Use this if the reverse tunnel is up but connections through it close before the SSH banner appears.

Make it permanent

Keep the tunnel alive automatically

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/3dvr-reverse-tunnel.service <<'EOF'
[Unit]
Description=3DVR reverse SSH tunnel

[Service]
ExecStart=/usr/bin/ssh -i %h/.ssh/utunnel -o BatchMode=yes -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -o StrictHostKeyChecking=yes -N -R 127.0.0.1:2206:127.0.0.1:22 root@167.233.174.20
Restart=always
RestartSec=10

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable --now 3dvr-reverse-tunnel.service
systemctl --user status --no-pager 3dvr-reverse-tunnel.service

Run this after closing the manual tunnel. It moves the connection out of Terminal so it can reconnect automatically.

Ubuntu Touch power

Keep remote access alive with screen off

mkdir -p ~/.config/systemd/user
cat > ~/.config/systemd/user/3dvr-stay-awake.service <<'EOF'
[Unit]
Description=Keep Ubuntu Touch active for 3DVR remote access
Before=3dvr-reverse-tunnel.service

[Service]
ExecStart=/usr/sbin/repowerd-cli active
Restart=always
RestartSec=5

[Install]
WantedBy=default.target
EOF
systemctl --user daemon-reload
systemctl --user enable --now 3dvr-stay-awake.service
systemctl --user restart 3dvr-reverse-tunnel.service

Uses Ubuntu Touch's native repowerd inhibitor: the display may turn off, but the device does not suspend while remote access is enabled.

Daily-driver upgrade

Upgrade Ubuntu Touch to OTA-12

sudo system-image-cli --switch 20.04/arm64/android9plus/stable

Verified stable feed for this OnePlus 6/6T port. Downloads the current Focal OTA-12 system image, then reboots to apply it. Your home data and 3DVR remote-access files stay in /home/phablet.

OTA diagnostics

Expose OTA error log

sudo mkdir -p /home/phablet/ota-debug
sudo cp /root/.cache/system-image/client.log /home/phablet/ota-debug/root-client.log
sudo cp -a /var/lib/system-image /home/phablet/ota-debug/system-image-state
sudo chown -R phablet:phablet /home/phablet/ota-debug
echo OTA_LOG_READY

Copies only the updater diagnostics/state into your home directory so 3DVR can inspect the failure remotely.

OTA diagnostics

Capture OTA failure safely

mkdir -p ~/ota-debug
sudo sh -c 'system-image-cli -n -v --switch 20.04/arm64/android9plus/stable > /home/phablet/ota-debug/ota-dry-run.log 2>&1'
sudo chown phablet:phablet ~/ota-debug/ota-dry-run.log
echo OTA_DRY_RUN_READY

Runs the updater as root in dry-run mode, captures the exact failure to your home directory, and does not reboot or apply the update.
